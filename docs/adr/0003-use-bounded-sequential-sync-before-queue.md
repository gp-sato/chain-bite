# 初期MVPは期限付きの逐次同期とし、Queueを後回しにする

**Status: accepted**

NexusFeedでは、画像取得をQueueへ分離した後に、送信タイムアウト、冪等性、重複配信、`PROCESSING` のクラッシュ復旧、DB保存とQueue投入の取りこぼし、Sweeperが必要になった。ChainBiteの初期MVPでは、4ブランドのアダプターを1つの日次Cron内で順次実行し、ブランドごとのHTTPタイムアウトと限定的なリトライを適用して、DBへUPSERTする。Queueは処理量や実行時間の実測から非同期化が必要だと判断した時点で導入し、その際は [`nexusfeed-lessons.md`](../nexusfeed-lessons.md) に記録した復旧・冪等性の条件を満たす。

## Considered Options

- 初期から全ブランドをQueueへ投入する
- ブランドごとに別Cronを用意する
- 1つの日次Cronで期限付きに順次同期する（採用）

## Consequences

- 初期構成が小さく、障害の境界とデータ保存の流れを追いやすい
- 1回の同期で処理できるブランド数・外部リクエスト数には上限がある
- 実行時間が不足した場合は、アダプター単位の結果と次回再取得の方針を追加する必要がある
- Queue導入時に必要となる状態管理・復旧処理を、要件がない段階で先に抱え込まない
